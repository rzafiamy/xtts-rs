# AGENTS.md

Guidance for AI agents working in this repository.

## Project

Rust/Candle port of Coqui XTTS-v2 (multilingual TTS, ~470M params; weights
under the Coqui Public Model License, non-commercial). One binary (`xtts`),
models from the Coqui checkpoint directory or one GGUF file written by
`xtts convert`.

Architecture: text → BPE (`vocab.json`) → GPT-2 (30 layers, 1024 wide, no
built-in position embedding) over `[32 conditioning latents | text | audio
codes]` with learned per-segment position tables → one audio code per 1024
samples at 22.05 kHz (~21.5 codes/s) → the `final_norm` latent of each code →
two linear interpolations (x4, then 22.05 → 24 kHz) → HiFi-GAN conditioned on a
512-d speaker embedding → 24 kHz audio.

## Where things are

- `crates/xtts/src/gguf.rs`: `.pth` reading (candle pickle), weight-norm
  folding, GPT-2 `Conv1D` transposition, built-in voices, GGUF layout.
- `crates/xtts/src/gpt.rs`: the GPT with KV cache; embeddings on the CPU.
- `crates/xtts/src/sampling.rs`: HF `generate` order (repetition penalty,
  temperature, top-k, top-p).
- `crates/xtts/src/hifigan.rs`: decoder, interpolation, `StreamDecoder`
  (windowed decoding on the one-pass frame grid).
- `crates/xtts/src/text.rs`: `tn` normalization (fr/en), XTTS cleaners
  (`text_tables.rs`, generated by `scripts/gen_text_tables.py`), sentence
  splitting, tokenizer.
- `crates/xtts/src/model.rs`: `Xtts` (load, voices, `generate_codes`,
  `synthesize`, `synthesize_stream`).
- `crates/xtts-cli/src/`: CLI (`main.rs`) and HTTP server (`server.rs`).
- `scripts/ref.py` + `crates/xtts/examples/parity.rs`: greedy parity against
  coqui-tts; `examples/bench.rs`: latency; `scripts/vram.sh`: server VRAM;
  `scripts/wer.py` / `scripts/ref_wer.py`: intelligibility (ASR WER).

## Commands

```bash
cargo build --release -p xtts-cli
cargo test --release --workspace
xtts convert <coqui-dir> -o models/xtts-v2-q4k.gguf --gpt-dtype q4k [--no-cloning]
./build.sh --cuda      # release binary in build/ (zallama's build-xtts.sh calls it)
xtts speak -m models/xtts-v2-q4k.gguf -l fr "Bonjour." -o out.wav
cargo run --release --example parity -- <coqui-dir> <ref.safetensors> fr "<text>" --cpu
```

CUDA: `--features cuda`, build into `--target-dir target-cuda`, needs
`/usr/local/cuda/bin` in PATH and `CUDA_COMPUTE_CAP`.

## Rules

- coqui-tts 0.27 (`TTS/tts/models/xtts.py`, `TTS/tts/layers/xtts/`) is the
  spec. Check model changes with the parity example: greedy codes must match
  exactly from the F32 checkpoint (CPU or GPU); latents ~1e-5, decoder ~79 dB.
- Coqui decodes the latent that produced the stop code too, and the
  repetition penalty starts with ids 1 and 1024 (the prompt ids `generate`
  sees).
- `StreamDecoder` needs ≥ 12 frames of lookahead and context (receptive
  field); fewer gives audible seams.
- Measure quality with `scripts/wer.py`, not by ear alone; XTTS babbles after
  the last word with its default sampling, the reference included.
- candle 0.11: `matmul` with a stride-0 batch (`broadcast_left`) returns wrong
  values (see `weights.rs`); F16 activations are slower than F32 with
  quantized weights; the F16 decoder loses quality (27 dB).
- Tail babble (extra syllables after the last word: "point", "Pinto") is
  the model's, not the port's (greedy Coqui gives the same codes). It comes
  from the final period: `text::drop_final_period` removes it from each
  chunk (WER fr 1.1 → 0.6 %, en 0.5 → 0.0 %; the ~170 ms end silence and
  the pauses between sentences of a chunk are unchanged). tn adds a final
  period, so this runs after normalization. Temperature/top_p barely
  matter (sweep 0.3-0.75 / 0.5-0.85: same WER). P(stop) stays below 1e-3
  until the stop code is drawn, so `stop_prob` cannot cut babble. German
  babbles even in greedy Coqui; zallama offers fr/en only.
- `--no-cloning` drops the conditioning encoder, perceiver and speaker
  encoder (125 MB of a 401 MB q4k file). They are F16/F32 and stay on the
  CPU, so VRAM is unchanged; voice cloning is not implemented yet anyway.
- VRAM (RTX 4090, q4k): 776 MiB idle / 1032 MiB peak, of which 428 MiB is
  the bare Candle CUDA context (`examples/vram_floor.rs`). WER (Parakeet,
  `scripts/wer.py`): q4k 1.2 % fr / 0.5 % en; q6k and q8_0 are no better.
  CPU: ~0.4x real time.
